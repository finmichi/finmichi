# 科目選擇與歷史資料

共用 `ItemPicker` 的斷點為 900px。電腦版依完整父路徑分組；手機版先選大類別，再選子科目，可返回或直接搜尋完整路徑。就地新增維持原流程。

- `posting`：只提供未封存、沒有未封存直屬子科目的末端科目。既有選取的父科目或封存科目仍顯示「歷史科目，無法再選」；未更換的設定欄位可以儲存。
- `filter`：查詢與帳戶異動可選父科目及封存科目，沿用既有查詢 API 的子樹語意。封存科目放在最後的「已封存」群組；手機提供「全部 ⟨大類別⟩」。
- 預算使用 `filter` 搭配 `purpose="budget"`，父科目顯示完整路徑，不加「含子科目」。父子可同時編列，`budget_own`、`budget_rollup`、`actual_rollup` 與封存處理均不變，API 不套用記帳科目的限制。

最近使用最多八筆，儲存在 `finmichi-recent-items`，依帳本與欄位分開；快速記帳另依收入／支出／轉帳及來源／目的隔離。讀寫失敗不影響使用；不顯示已刪除、已封存或已成為父科目的最近項目。filter／預算不讀寫最近使用。

## 服務邊界

新交易或新選用的記帳科目有未封存直屬子科目時，回 `400 parent_item_not_postable`。檢查位於持有帳本鎖的 service transaction 內；新增子科目仍允許。

交易整筆替換分錄時，依舊分錄的科目 ID 多重集合保留歷史科目使用次數，允許分錄重排，不允許複製出更多父科目分錄。既有封存分錄的原金額／匯率保留規則仍適用。週期規則與投資、股利所得代碼、定存、卡片／貸款設定依未變更欄位保留；新增實際入帳仍走交易驗證。

Life2023 歷史匯入以內部明確旗標略過父科目限制；E-Money 歷史轉入與 JSON 還原沿用既有路徑。REST／MCP 不接受任何略過檢查旗標。金額計算、權限與 audit 口徑不變。

本 PR 無 migration，不改資料表或已合併的 migration。歷史父科目分錄不搬移、不重算。測試以合成歷史分錄、CSV 匯入及 JSON 還原驗證既有查詢筆數與金額。
