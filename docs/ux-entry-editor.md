# P1.6 第三批：記帳與編輯覆蓋層

依 UX rev.1.2 §8.3、§3、§12，沿用既有交易／catalog API；沒有新增 API、SQL、migration、依賴或金額換算規則。

## 版面與入口

桌面 ≥900px 為420px右側 Drawer，手機為全螢幕；共用28px等寬靠右金額輸入、正式AA token、可搜尋科目／收付人／專案，以及 EdgeScroll。欄位依序為快捷類型、金額、來源／目的、日期、外幣匯率、收付人／專案、摘要／常用摘要與可收合發票欄位。進階模式保留2～100筆分錄。

`?entry=new`與`?entry=<id>`保留目前路徑與所有篩選。首頁、明細、管理／報表入口、N快捷鍵與點交易列皆開啟同一覆蓋層，背景頁面保持掛載；關閉後保留原篩選／捲動，焦點回觸發元素。交易或catalog更新以事件使既有唯讀查詢重新讀取，編輯後保留已載入的cursor前綴，不縮回第一頁。

## 互動與寫入

- 支出／收入／轉帳提供相應來源／目的科目選項；最終kind仍由既有service依分錄推導，不送kind欄位。編輯保留原有科目，包括既有調整類型；封存分錄的限制沿用既有行為。
- 選單底部「＋ 就地新增」即使搜尋無結果仍可使用。科目小表單提供名稱、kind、幣別、同kind父科目、業外／固定性；收付人／專案可就地建立。成功後加入選單並自動選取。沿用catalog API，新增資料即時保留，取消交易不會刪除已建立的catalog資料。
- 常用摘要以可水平捲動晶片帶入完整內容；文字保留換行，發票欄位可收合。
- 完整有效輸入停止變更350ms後呼叫既有preview API；不在前端計算base。序號／cleanup丟棄過時回應，原「試算交易」按鈕仍可重試。分錄預覽顯示科目、帶號原幣、本位幣與完整匯率；錯誤沿用中文對照。
- 情境C有效匯率、參考來源與偏差皆讀API；畫面偏差HALF_UP到2位。超過5%使用warn token顯示中文警告，確認後可儲存；修改輸入會使舊試算與確認失效。
- 儲存／修改／刪除全部沿用既有交易service；成功後關閉並以5秒Toast通知。桌面另有「儲存並新增下一筆」。未知交易讀取404時，表單與儲存保持不可用，不能誤建立新交易。

## 未儲存保護

Esc、遮罩、取消、頁內導覽與瀏覽器返回均先經頁內確認：繼續編輯保留內容，捨棄才執行原動作，沒有window.confirm。輸入與busy狀態以layout effect同步到guard；單一全域popstate處理器先確認才發佈路由，避免Window監聽器註冊順序使表單提前卸載。未完成寫入時不允許關閉。

重新整理／關閉瀏覽器分頁使用標準beforeunload保護；其提示外觀由瀏覽器控制。草稿不寫入localStorage或DB。

## 驗證與回復

`pnpm check`、`pnpm test:db`、既有七組UI、foundation／daily矩陣，以及新增`pnpm test:ux-entry`。新矩陣涵蓋四尺寸×淺深×7狀態56PNG（快速、預覽、dirty確認、編輯、進階、就地新增、外幣警告），axe color-contrast、無水平溢出；另以HTTP→DB驗建立／修改、就地新增三種資源與自動選取、收入模式、404保護、連續新增、返回拒絕／接受及多頁編輯捲動。

只用合成資料。完成本批後停止等待Claude驗收；PR4／5及P2未開始，不部署DS918+或建立tag。回復可revert本PR，沒有DB遷移或資料轉換。
